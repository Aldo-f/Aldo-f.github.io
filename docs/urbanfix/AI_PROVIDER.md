# AI Provider Interface Specification

## Overview
This document describes the public interface of the AI service layer (`server/services/ai.ts`).  It is used by the frontend and other backend components to request AI‑powered analysis, report generation and email handling.

| FREELLM_API_KEY | Key for the FreeLLM DuckDNS proxy (fallback). |

> **Note:**  The application loads these variables via `process.env`.  Only `GEMINI_API_KEY` is strictly required for the default configuration; all others are optional depending on the waterfall setup in `settings.aiWaterfall`.

## 3. Provider Fallback Order
The AI service uses a **waterfall** strategy defined in `settings.aiWaterfall.providers` (priority low → high).  By default the order is:
1. **Google Gemini** (`providerType: "google"`).
2. **OpenAI‑compatible providers** (`openrouter`, `openai_compatible`, `groq`, `custom`).
3. **Custom/local providers** (e.g., Ollama via `custom` endpoint).

When a provider fails (network error, rate‑limit, or missing key) the service automatically retries the next provider in the list.

---

## 4. Rate‑Limit & Retry Policy
* **Exponential back‑off** – on HTTP 429 or network failures the request is retried with a back‑off factor of 2 (e.g., 500 ms → 1 s → 2 s) up to three attempts per provider.
* **Maximum request rate** – consumer code should respect a soft limit of **30 requests per minute per provider**.  This is not enforced by the code but documented for operators.
* **Timeout** – each provider call is cancelled after the configurable `waterfall.timeoutSeconds` (default 10 s).  If the timeout expires the next provider is tried.
* **Deterministic fallback** – when *all* providers fail the service returns a deterministic, template‑based response (see `analyzeDefect` fallback block) so the API never throws an uncaught error to the client.
